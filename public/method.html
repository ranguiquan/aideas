方法论

平时只管记，判断留到复盘

信息台里的数据由三个 Claude 技能写进 Notion。它们分工很简单：看到东西随手记，有日程的事件按提醒跟，隔一段时间统一复盘，决定哪些继续跟、哪些放掉。

说「记进库里」。Claude 先问你一句话结论，再存进信息库。

几条规矩

小结自己写

入库前 Claude 会先问你「这段你得出了什么结论」，你的原话照抄进「一句话小结」，不润色。懒得写就空着，复盘时再补，不会拿 Claude 的总结顶上。

原因：先看了 AI 的总结，人很容易顺着它想，复盘时也分不清哪些是自己的判断。

记的时候不做决定

新记录一律是「待处理」。值不值得跟进、要不要归档或放弃，都等复盘时再说。

这样记一条只要几秒钟，不会因为要想清楚而拖着不记。

预期必须在事件前写

事件发生后才写的「预期」不算数，只能记成结果，并注明没有事前预期。

例：CPI 公布后再写「我本来就觉得会高」，这条没有参考价值。

决策看理由，不看赚没赚

回看一笔操作时，只判断当初的理由有没有应验：理由成立 / 部分成立 / 理由不成立。盈亏另外写。

例：赚了钱，但涨的原因跟你当初想的不一样，那就是「理由不成立」。

猜错了也要结案

追踪主题有了结论就结案，结论可以是「推翻」。只有不了了之的才记「已放弃」。

猜错的记录最能告诉你自己哪类判断不靠谱，别把它们藏进「放弃」里。

同时跟的东西别太多

追踪主题同时保持 3–5 个。「跟进中」的记录越积越多时，复盘会提醒你砍掉一些。

跟进中的每一条，都意味着你真要花时间去做它的「下一步」。

两个库，互相关联

「信息与灵感库」放读到的、想到的、做过的操作；「计划与关注」放你在跟踪的判断（追踪主题）和用来检验它们的事件。

三个技能

记进库里 notion-info-vault

把一段讨论或一篇文章存进信息库。关键是小结由你来写。

  1. Claude 问你一句话结论，不先给自己的版本
  2. 你说完，Claude 补充或反驳两三点，并草拟「下一步」
  3. 你确认后写入 Notion，状态设为「待处理」
  4. 如果是某条旧记录的后续，挂上「衍生自」；明显属于某个主题的，挂上「相关计划」

计划事件 plan-event-tracker

只处理跟时间有关的事：加事件、写预期、补结果、改期或取消。

  1. 用网络搜索核实官方日期，按新加坡时间记录
  2. 挂到一个进行中的追踪主题；找不到合适的就问你，不会为了挂靠新建主题
  3. 自动建两个提醒：写预期、补结果
  4. 事件改期，提醒跟着改；事件取消，提醒一并删除
把下周 CPI 加进计划写个预期补一下结果XX 改期了

复盘 periodic-review

唯一做判断的环节。Claude 负责汇总和给建议，决定都由你做。

  1. 从上一次复盘开始算区间；第一次默认过去 7 天
  2. Claude 生成一屏左右的摘要，最后问你三个问题
  3. 你回答几句，Claude 只改你明确说了的东西
  4. 在计划库留一条「复盘 YYYY-MM-DD」，作为下次的起点
复盘回顾一下回顾过去两周只有 10 分钟

摘要里有什么

  1. 主题信号 最近反复出现的方向
  2. 待处理分拣 每条给建议：跟进 / 归档 / 放弃
  3. 跟进中检查 下一步做了没有，停滞的建议降级
  4. 决策回看 回看日到了的操作，核实理由是否应验
  5. 事件回看 漏补的结果、预期 vs 实际
  6. 接下来的事件 哪些还没写预期
  7. 该复查的主题 检验事件都过了的，问要不要结案

最后三个问题：什么反复出现、值得追踪？什么改变了你的看法？接下来带着什么问题看信息？

状态怎么变

记的时候只会出现「待处理」和「待发生」。其他状态变化都发生在复盘或事件提醒里，并且由你确认。

信息 / 灵感

待处理复盘 → 跟进中做完 → 已归档或 已放弃
