Notion × Claude · 个人信息流管理

三个 Claude 技能，两个 Notion 数据库。信息和想法随手入库，与主题相关的事件按日程提醒，所有取舍留到复盘时由你自己来做。

原则

这套机制在防什么

每条规则都在对付一种具体的失真：AI 替你下结论、事后诸葛亮、把运气当判断力、积压冒充投入。

「一句话小结」必须是你的原话

谁先写总结，谁就框定了复盘时的第一印象。Claude 先问、不先给；你的话再粗糙也逐字照录，不润色。不想写就留空，复盘时再补。

记进库里 · 小结对话

捕获时不做判断

新记录一律是「待处理」，不论讨论看起来多完整。跟进、归档、放弃、新建主题，都是复盘时的事。

记进库里 · 状态

预期必须在事前写

事后写的预期会被结果污染。事件已经发生，就只能写进「结果」，并注明「事后记录，无事前预期」。

计划事件 · 写预期

判定看理由，不看盈亏

赚钱但理由没应验，是理由不成立；亏钱但理由应验，可以是成立。两者分开记，累积下来才能分清判断力和运气。

复盘 · 决策回看

被推翻是结案，不是放弃

有定论就结案，哪怕结论是推翻。把推翻记成放弃，会抹掉最有校准价值的数据。

复盘 · 追踪主题

跟进中是承诺，不是积压

进行中的追踪主题保持 3–5 个。「跟进中」代表你承诺投入的时间，数量持续增长时 Claude 会提醒你取舍。

低摩擦捕获，先问你怎么想

入库前 Claude 先请你用一两句话说出结论，不先给自己的总结。你说完后，它补充或反驳两三点，顺带草拟「下一步」请你确认，然后才写进 Notion。

  1. 识别要归档的是哪一段对话
  2. 请你写原话小结，Claude 回应补充与反驳
  3. 你定稿，一并确认「下一步」
  4. 判断衍生关系、是否挂到进行中的主题
  5. 写入 Notion，状态设为「待处理」

只处理「时间不等人」的动作

计划库的调整原则上留给复盘。这个技能只管事件：加事件、写预期、补结果、改期或取消。每个事件自动配两个一次性提醒，写预期不必等到下次复盘。

  1. 核实官方日期，按新加坡时间（UTC+8）记录
  2. 挂到一个进行中的追踪主题；找不到就问你，不为挂靠新建主题
  3. 写一句「检验点」：这个事件对主题意味着什么
  4. 创建写预期、补结果两个提醒，trigger ID 记在页面里
不批量导入整份经济日历。只录入与进行中主题相关的事件，因为每个事件都会带来两个提醒。

Claude 整理，你来取舍

复盘没有固定周期，可以由每周的定时提醒触发，也可以随时手动开始。区间起点取上一条「复盘」记录的创建时间。跳过的复盘不补做，区间长就压缩呈现。

  1. 阶段一：Claude 取数、聚类，生成约一屏的摘要，末尾问三个问题
  2. 阶段二：你回答几句，Claude 只执行你明确表达的变更
  3. 写一条「复盘 YYYY-MM-DD」记录，作为下次的起点
定时触发时只发摘要，停在阶段一：不代你回答，不改任何状态。

摘要末尾固定的三个问题

  1. 这段时间什么东西反复出现，值得作为主题追踪吗？
  2. 有什么信息改变了你原来的看法？
  3. 接下来你要带着什么问题去看信息流？

生命周期

状态什么时候变，由谁来变

捕获只会产生「待处理」和「待发生」。其余每一次状态变化，都要经过复盘或事件技能，并由你确认。

信息 · 灵感记录

信息与灵感库

待处理复盘 → 跟进中下一步完成 → 已归档 或已放弃

完成情况看「衍生出」和「相关计划」，不靠状态本身。停滞两次复盘的，建议降级。

决策

信息与灵感库 · 类型=决策

待处理复盘 → 跟进中回看日到期 → 已归档 判定：理由成立部分成立理由不成立

缺理由的，分拣时是最后一次补记机会，注明「事后补记」。延长观察就改回看日，保持跟进中。

追踪主题

计划与关注 · 类型=追踪主题

进行中有定论 → 已完成（结案） 判定：证实部分成立推翻

没有定论就失去兴趣才是「已放弃」，判定留空。结案或放弃时，逐个处理名下还没发生的检验事件：取消或改挂。

日程事件

计划与关注 · 类型=日程事件

待发生补结果 → 已完成 或 取消 →已放弃

改期时两个提醒一起重算；取消时删掉还没触发的提醒。
